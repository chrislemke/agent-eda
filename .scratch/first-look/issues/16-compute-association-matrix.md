# 16: compute_association_matrix

**What to build:** An agent calls `ae.compute_association_matrix(df)` and sees how strongly every suitable pair of numeric and categorical columns is associated, strongest first. The result records the method for each pair and computes each pair on its own complete rows. Perfect associations are flagged as possibly duplicated or derived columns, directional measures carry their direction, and skipped columns come with reasons. Numeric codes the agent lists as categorical count as categories, so codes such as 1, 2 and 3 aren't correlated as numbers. The analysis lives in `agent_eda.statistics.association`.

This is the largest analysis. With 100 columns there can be 4,950 pairs on 1M rows, so a pandas crosstab per pair can't meet the 5-second target. Factorize each column once and count on integer codes.

Read these sections of `.scratch/first-look/spec.md`: the compute_association_matrix entry under The first-look analyses, Analysis results, and test group 2 under Testing Decisions. Covers user stories 39, 58, 109 to 114 and 116.

## Comments

What this ticket settled that the spec left open:

- **Where things live.** `agent_eda/statistics/association.py` holds the analysis: column selection and classification, skip reasons, statuses, findings and limitations. `agent_eda/_association.py` holds the measures: `measure_pairs` computes every pair at once, and `numeric_pair`, `categorical_pair` and `mixed_pair` compute one pair exactly. `ComputeAssociationMatrixResult`, `AssociationPair`, `AssociationColumn` and `SkippedColumn`, with the literals `AssociationMethod`, `AssociationType`, `SkipReason` and `UndefinedReason`, sit in `agent_eda.results`.
- **Columns.** `columns=None` selects the numeric, boolean, text, object and categorical columns in DataFrame order, and every other column lands in `skipped_columns` with reason `datetime`, `timedelta` or `unsupported_dtype` (pyarrow lists, periods, intervals). A datetime or timedelta column named in `columns` raises `ColumnTypeError` with conversions, as the calling convention asks of a column the analysis can't handle. The skips that depend on the data apply to named columns too: `all_missing` (it needs at least one row, as in describe_dataset), `no_finite_values` (a numeric column holding only inf and -inf), `unhashable_values` (lists or dicts) and `too_many_categories`. Each skipped entry has `column`, `dtype`, `reason` and a one-sentence `message`, in DataFrame order for `columns=None` and in the given order otherwise.
- **`categorical_columns`** goes through the shared column rules: an unknown name raises `ColumnNotFoundError`, an empty list or a repeated name raise, and a datetime or timedelta column raises `ColumnTypeError` suggesting `.dt.strftime('%Y-%m')` or `.astype(str)`. Naming a boolean, text or categorical column changes nothing. With explicit `columns`, a name outside them raises `InvalidArgumentError`: "Add it to columns, or leave it out of categorical_columns". The parameters record the checked list, `[]` for None. A numeric column read as categorical is factorized on its own values, so integers beyond 2^53 stay distinct, and NaN is missing even where the dtype stores it as a value, as in summarize_numeric. Such NaN gets the `nan_counted_as_missing` limitation, as it does in a numeric column. Levels are the distinct values present, so unused categories don't count.
- **Levels probe.** A column with more than 20,000 rows first counts the levels in its first 20,000 rows. More than `max_categories` there means more in the column, so it is skipped without factorizing the rest. On the benchmark this saves about 1.1 s on pandas 2.2, whose object text factorizes slowly.
- **Pairs.** One `AssociationPair` per pair, with `x_column`, `y_column`, `x_type`, `y_type`, `method`, `value`, `pair_count`, `direction` and `undefined_reason`. x is the earlier column in the selected order, except in a correlation ratio, where x is the categorical and y the numeric column and `direction` is `x_to_y`; every other measure is `symmetric`. Pairs come strongest first by absolute value, ties in the selected order, null values last. The result's `method` is null and the registry's `methods` empty, since the method varies by pair; the parameters and the printed facts name them. Instead of per-column statuses, a column is either paired, with an entry in `columns` keyed by name (type, value, missing and infinite counts, levels), or skipped with its reason, and each pair carries its own `undefined_reason`.
- **Complete rows** hold both values, present, and finite in a numeric column, so infinite values are left out, as in summarize_numeric. A null value has one of these reasons, checked in this order: `too_few_rows` (fewer than 3), `single_level` (a categorical column with one level in them), `one_row_per_level` (a categorical column with a level for every complete row, such as an ID) and `constant_column` (a numeric column with one value in them). A column with a level for every row explains any other column perfectly and trivially: the correlation ratio and the plain V would be 1, which would also raise false `perfect_associations`, and Bergsma's correction divides by (k - 1)(n - k) / (n - 1), which is 0 there. So every measure with such a column is null. Limitations name the null pairs by path, such as `pairs[3].value`: `too_few_values` for too_few_rows and one_row_per_level, `zero_variance` for single_level and constant_column. Numeric columns are read with the shared `read_numeric`, so `float_precision` and `nan_counted_as_missing` come from the shared `read_limitations`.
- **Statuses.** `completed` when at least one pair has a value. `insufficient_data` with code `no_rows` for data without rows, where no pair is computed, or `no_defined_pairs` when every pair is null. `not_applicable` with `fewer_than_two_columns`. `budget_exceeded` with `too_many_pairs`: the limit is checked after the work per column (reading and factorizing each column once, linear in the rows) and before any pair, and the message gives the paired columns, the pair count, the limit and both fixes, naming fewer columns or passing `max_pairs=<pair count>`. `failed` is declared without a code path, as in the other analyses.
- **Finding.** `perfect_associations` (suspected) flags an absolute value of at least 1 - 1e-9; rounding leaves an exact relation a few ulps short of 1. Its claim and fields list the pairs in column order, not value order, so ulp differences can't reorder them.
- **Tables.** `to_frame(table="pairs")`, the default, has every pair. `to_frame(table="matrix")` has the paired columns as rows (`x_column`) and columns (`y_column`): a symmetric measure fills both cells, a correlation ratio only the cell from its categorical row to its numeric column, and the diagonal stays NaN, so no directional measure is forced into a symmetric matrix. An unknown table raises `InvalidArgumentError` listing the tables and the closest one, from `_check_table` in `agent_eda/results.py`. A table argument that isn't a string shows as its type and size, such as "a pandas Series of 2 values", through `value_text`, which moved from the registry to `_text.py` so both share it and no data reaches a message. A fact line of the printed summary names both tables. Ticket 10 builds a `table` literal too; whichever merges second keeps one mechanism.
- **Text.** The facts give the pairs per kind with their methods, the skipped columns with their reasons, and the tables; the key table shows x_column, y_column, method, value, pair_count and direction. The fact lines stay within about 112 characters, so the docstring example fits the 124-character lint limit.
- **Search.** The tags are correlation, association, cramers v, pearson, spearman, kendall, correlation ratio, related, relationships, dependence and redundant. "correlation" finds it first through the synonym association in its name, and "which columns are related" now does too. summarize_numeric's and describe_dataset's `When to use:` and `See Also:` point to it, describe_dataset's for columns whose values, not labels, duplicate each other.
- **Execution** lists scipy only when Kendall computed a value. Pearson, Spearman, Cramér's V and the correlation ratio are NumPy.

How it computes:

- `measure_pairs` reads the pairs off a few matrix products over chunks of rows, so the work grows with the rows times the squared count of numeric columns and levels, not with the rows times the pairs. Each numeric column is divided by a power of two near its largest absolute value, which is exact and keeps squares from overflowing, and centred once on the mean of its finite values in evenly spaced rows. A float32 product of the one-hot levels (missing codes go to a spare column) with the finite masks gives the rows per level where each numeric column is finite and the numeric pair counts, and a float32 SYRK of the levels of the categorical columns with at most 12 levels gives the contingency tables among them; counts stay exact because a chunk has at most 65,536 rows. float64 products give the per-level sums of each numeric column, the numeric sums, squares and cross products, and the squares of each numeric column where each categorical column is missing. A chunk's buffers take about 32 MiB.
- A numeric pair or a correlation ratio comes from these sums only when, in the pair's complete rows, the sum of squares about the pair's mean keeps at least a quarter of the sum of squares about the column's centre, and the mean square stays clear of subnormals. Otherwise the pair is computed again in two passes on its own complete rows. That catches a column constant in the pair's rows, and rows far from the column's centre, such as values near 1e6 where the other column is present and 0 elsewhere. The between-level sum of squares is the sum of n_l (mean_l - mean)^2, which can't cancel. Every reference test, batched or not, matches SciPy within 1e-12.
- Two traps, each with a regression test. Values such as 1e15 plus small integers subtract exactly from their mean, but the mean itself is rounded by a visible share of their spread, so the two-pass path subtracts the mean twice; with one pass, r was off by 8.5e-5. And the power of two that scales subnormal values up overflows float64, so those columns are scaled with `np.ldexp` instead of a multiplication, which had raised a spurious `numerical_warning`.
- The other categorical pairs are counted pair by pair: one bincount of the joint codes, built from codes shifted by 1 once per column into a reused buffer, about 1.6 ms per pair per million rows on both version sets. The SYRK costs about 1 ps per pair of levels per row with Accelerate and 9 ps with OpenBLAS, so it wins up to about 13 x 13 levels even on OpenBLAS; hence the 12. The review found the earlier rule, one SYRK of every table when the columns averaged up to 24 levels, 2.4 times slower than counting at 24 levels on OpenBLAS (27.8 s against 11.6 s for 90 such columns). A categorical column with more than 64 levels, possible only with a raised `max_categories`, gets its correlation ratios pair by pair too. A table of more than 2^22 cells is built from the cells that occur, so two columns of 100,000 levels don't allocate 10^10 cells: chi2 adds the expected counts of the cells that don't occur as the rows less the expected counts of those that do. `max_categories` has no upper bound.
- The bias-corrected V snaps a numerator `phi2 - (k - 1)(r - 1) / (n - 1)` within 64 ulps of phi2 to 0, so an exact 0 doesn't come out as the square root of rounding, about 1e-8.
- Spearman and Kendall go one pair at a time: Kendall through `scipy.stats.kendalltau` with `variant="b"`, Spearman with NumPy's ranks. Spearman ranks a column once for every pair whose complete rows hold all its finite values: on complete data, 45 pairs of 1M rows take 1.6 s instead of about 9 s.
- With OpenBLAS, the float64 sums depend on the number of BLAS threads in their last ulp: between 1 and 2 threads, 42 of 153 values in the review's frame changed in the last digit. Identical calls with the same thread count give byte-identical JSON, in one process or several; Accelerate is the same for any count. The spec's identical JSON holds within one environment, and the BLAS thread count is part of it.
- Don't call `scipy.linalg.blas` directly. On the minimum versions its `dgemm` took 97 s where NumPy's matmul took 0.33 s on the same arrays, probably two OpenBLAS libraries competing for threads. NumPy's `A.T @ A` already uses SYRK.
