# 15: profile_target

**What to build:** An agent names the target column and the task, and `ae.profile_target()` describes the target for that task. For classification that means class counts, shares and imbalance, plus missing labels, labels outside the expected set and, when the agent gives a threshold, rare classes. For regression it means the numeric summaries. The analysis flags targets that don't fit the task, such as a single class or a constant regression target, before the agent trains anything. It never infers the task from the dtype, so a numeric class label isn't mistaken for a regression target.

The analysis lives in `agent_eda.data.targets` and reuses summarize_numeric's implementation for regression.

Read these sections of `.scratch/first-look/spec.md`: the profile_target entry under The first-look analyses, Row IDs, and Project, data policy and masking. Covers user stories 106 to 108.

**Blocked by:** 08-project-and-masking

**Status:** done

- [x] `target_column` and `task` are required. `task` is a literal of `binary_classification`, `multiclass_classification` and `regression`. `expected_labels` and `rare_share` are optional with no defaults, and `rare_share` lies between 0 and 1. `id_column`, `project` and `mask_sensitive` work as in find_duplicate_rows.
- [x] For classification, the result gives the class counts and shares over valid labels, the number of classes, the majority and minority shares, the imbalance ratio, the missing labels, the labels outside `expected_labels` with counts and example row IDs, and the rare classes when `rare_share` is given.
- [x] For regression, the result gives summarize_numeric's fields for the target, from the same implementation, plus the count of non-finite values.
- [x] Without `expected_labels` or `rare_share`, the checks that need them don't run, and the result says they weren't checked.
- [x] A single class, a binary task with other than two classes, labels outside `expected_labels` and a constant regression target each give a violation. A classification target whose values are all distinct gives a suspected finding. Missing labels and rare classes give descriptive findings.
- [x] A regression task on a non-numeric column raises `ColumnTypeError` suggesting a classification task or a conversion. An unknown `target_column` raises `ColumnNotFoundError` with suggestions.
- [x] With masking on and a sensitive target column, class labels and unexpected labels become placeholders, and so do row IDs from a sensitive `id_column`. Counts and shares stay.

## Comments

What this ticket settled that the spec left open:

- **Result fields.** `ProfileTargetResult` has one set of fields for both tasks, and the other task's fields are null, as each field's description says. Both tasks give `non_missing_count`, `missing_count` and `missing_share`. Classification gives `valid_label_count`, the denominator of every share (the labels that aren't missing, or with `expected_labels`, those in it); `class_count` and `classes`, each a `ProfileTargetClass` with `label`, `label_type`, `count` and `share`; `majority_share`, `minority_share` and `imbalance_ratio`, the majority count over the minority count, which is 1 for a single class; `unexpected_label_count` and `unexpected_labels`, each with its `count` and the IDs of its first 10 rows; and `rare_class_count` and `rare_classes`. Regression gives `statistics` and `non_finite_count`, the missing plus the infinite values. `level_order` states the order, as summarize_categorical's does. The result object and the record keep 100 classes, unexpected labels and rare classes, with totals from the count fields (`_Cap(total=...)`), and 10 row IDs per unexpected label with `row_ids_total` from its count. `to_frame()` gives every label (`label`, `label_type`, `count`, `share`, null outside `expected_labels`, and the nullable booleans `expected` and `rare`, null when the check didn't run), or for regression summarize_numeric's frame row plus `non_finite_count`.
- **One implementation for regression.** `numeric_entry`, `numeric_support`, `NO_FINITE_VALUES` and summarize_numeric's defaults moved from `statistics/descriptive.py` to `_numeric.py`, and summarize_numeric's frame builder became `results._numeric_frame`; both analyses call them. `statistics` is a `ProfileTargetStatistics`, a subclass of summarize_numeric's `SummarizeNumericColumn` that only restates the `quantiles` and `trimmed_mean` descriptions, which named summarize_numeric's options. The ticket gives profile_target no quantile options, so it uses summarize_numeric's defaults and says so. A Hypothesis property checks that `statistics` equals summarize_numeric's entry on generated data.
- **Classes come from the shared level counting** in `_levels.py`, which gained `count_levels_by_row` (each row's level, for row IDs; `count_levels` stays as fast as before), `Levels.subset` and `ordered_among` (the first levels of a subset in the order of all levels) and `level_rows` (the frame rows that `levels_frame` uses too). A Hypothesis property checks the counts against pandas `value_counts`.
- **Which task takes which dtype.** Classification takes numeric, boolean, text, object and categorical columns; datetime, duration and other columns raise `ColumnTypeError` with a conversion to labels. Regression takes numeric columns only, so a boolean raises too, suggesting binary_classification. Each rejected kind gets its fix: `pd.to_numeric` for text and objects, `astype(float)` for categories and booleans, `dt.total_seconds()` for durations and the seconds since the earliest datetime. A classification target whose values can't be hashed raises `ColumnTypeError`, as an id_column does. `target_column` gets its `ColumnNotFoundError` from `select_columns`, with `parameter="target_column"`.
- **Matching labels.** A value matches an expected label when Python's `==` says so, the equality that forms pandas' levels, so 1 matches 1.0 and True, and text matches with its case and spaces. `rare_share` lies strictly between 0 and 1, and a class is rare when its share is strictly below it.
- **Caller mistakes** raise `InvalidArgumentError` before any computation: `expected_labels` or `rare_share` with a regression task; an empty list; a label listed twice (1, 1.0 and True count as one); NaN or infinity as a label; and other than 2 labels for a binary task or fewer than 2 for a multiclass one. A label of a type the target never holds, such as text for an integer column, raises once the target's labels are counted, the step that also finds values that can't be hashed, whose error comes first. That message names the label likely meant with `_sentinels.likely_value`, renamed from `_likely`, so declared sentinel values and labels parse text alike.
- **Findings.** `single_class` is a violation in both classification tasks. `more_than_two_classes` is a violation for a binary task with 3 or more classes; one class gives `single_class` alone, so a binary task with other than two classes always gets a violation. `unexpected_labels` is a violation, and `no_unexpected_labels` the passed finding when the declared check held on at least one label. `all_labels_distinct` is suspected when at least 2 values aren't missing and every one is distinct; that includes two rows of 0 and 1, a target no split can stratify. `constant_target` is a violation where summarize_numeric decides a column is constant (at least 2 values, all equal, `[inf, inf]` included). `infinite_values` is suspected, as in summarize_numeric, and `missing_labels` is descriptive for both tasks, as is `rare_classes`. Claims never name labels, so masking leaves them alone.
- **Statuses.** `insufficient_data` for data without rows (`no_rows`), a target without labels (`no_labels`), without a label in `expected_labels` (`no_valid_labels`) or, for regression, without a finite value (`no_finite_values`). Everything else is `completed`, a single class or one row included. `failed` is declared, but no code path returns it.
- **Checks that didn't run** leave their fields null, with the new limitation codes `expected_labels_not_declared` and `rare_share_not_declared`, whose reasons fit the printed line with their fix. The record of a null capped list is null, and so is its `<field>_total`; `_cap_growing_fields` used to fail on it.
- **Row IDs** appear only for labels outside `expected_labels`, so `ambiguous_row_ids` comes only when that check runs, as find_duplicate_rows adds it whenever its comparison runs. A regression, or a classification without `expected_labels`, shows no row ID, and a repeated index adds nothing. id_column may be the target itself; then a row ID is its label.
- **Masking.** `mask_levels` numbers all of a sensitive target's labels in level order, so a label shows the same placeholder in `classes`, `rare_classes`, `unexpected_labels`, the text and `to_frame()`. `expected_labels` in `parameters` become placeholders too, or the record would leak them: a label that occurs shows its class's placeholder, and one that never occurs gets a number after the target's labels, in the order given. Row IDs from a sensitive id_column go through `mask_values` in the order the labels show them; when id_column is the target, a row ID shows its label's placeholder. A regression target's statistics stay unmasked, and its masking line says so instead of "shows no value of a sensitive column"; `_masking_text` gained `statistics_columns` for that. The no-leak property's recipe makes a sensitive column the target, leaves some of its labels out of `expected_labels`, adds a stand-in label that holds the secret marker, and picks a sensitive id_column. Breaking the masking of class labels, of row IDs or of the recorded `expected_labels` on purpose failed the property each time.
- **Required options.** The registry gave pydantic `inspect.Parameter.empty` as the default of a parameter without one, so a call without `target_column` passed validation. Such options are now required, and leaving them out raises `invalid_call` naming them and the choices of a Literal one. An optional option with a range now states its range in errors ("float with 0 < rare_share < 1, or None") instead of "float | None". Ticket 13's `schema` meets the same code.
- **Contract.** `expected_labels` joined `NOT_COLUMN_NAMES`: it takes class labels, which can be text.
- **Search.** Tags: target, label, class balance, class imbalance, classification, regression target, rare classes and majority class. "class imbalance" scores 6, against 2 for summarize_categorical, whose When to use now names profile_target, and 1 for compute_association_matrix. Every earlier row still passes.
- **Neighbours.** describe_dataset, summarize_numeric and summarize_categorical name profile_target in `When to use:` and `See Also:`. The README's status line names it.
- **Guide.** It prints 56 lines now; detect_missing_sentinels and validate_column_types add about 3 more, within the 60.
- **Glossary gap.** "target", "class" and "label" (of a class) aren't in GLOSSARY.md, like "level" before; I left that for /domain-modeling.
