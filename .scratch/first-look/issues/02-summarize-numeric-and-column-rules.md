# 02: summarize_numeric and the shared column rules

**What to build:** An agent calls `ae.summarize_numeric(df)` and gets, for each numeric column, the counts and statistics the spec lists, each with its definition stated and checked against SciPy and NumPy. A statistic that doesn't exist for a column comes back as null with a reason, never as NaN.

As the first analysis that takes `columns`, it also sets the rules every later multi-column analysis reuses: how `columns` is resolved, per-column statuses and the overall status, numerical warnings recorded as limitations, and caller-mistake errors that say what's wrong, what's allowed and how to fix it. The analysis lives in `agent_eda.statistics.descriptive` and is written NumPy-first, per ADR 0002. Ticket 03's benchmark checks the 5-second target.

Read these sections of `.scratch/first-look/spec.md`: Calling convention, Analysis results, Statuses, Errors, Warnings, the summarize_numeric entry under The first-look analyses, and test groups 1, 2 and 6 under Testing Decisions. Covers user stories 27 to 31, 41, 55 to 57, 60, 61, 64 to 66, 95 to 97 and 117.

**Blocked by:** 01-describe-dataset-end-to-end

**Status:** done

Column rules and errors:

- [x] `columns=None` selects every numeric column except booleans, in DataFrame order. An explicit list keeps the caller's order. An empty list, a name listed twice or a column the analysis can't handle raises before any computation starts.
- [x] Every parameter that takes column names ends in `column` or `columns`.
- [x] An unknown column raises `ColumnNotFoundError`, a `LookupError`. The message lists the available columns and the closest matches, with case-insensitive matches first.
- [x] A text, categorical or datetime column requested by name raises `ColumnTypeError`, a `TypeError`, that names the column's dtype. Until summarize_categorical exists, the message names the dtypes summarize_numeric accepts, and ticket 06 adds the pointer to summarize_categorical.
- [x] A boolean column requested by name is read as 0 and 1, and a limitation says so.
- [x] An invalid `quantile_method` raises `InvalidArgumentError` listing the allowed values and the closest one. A `trim_fraction` outside the range from 0 up to but excluding 0.5, or a quantile level outside 0 to 1, raises with the valid range. All argument checks run before any computation.
- [x] summarize_numeric, like every later analysis except describe_dataset, raises `InvalidArgumentError` with a renaming hint when the DataFrame has duplicated column labels, labels whose string forms collide, or MultiIndex columns.
- [x] No raw pydantic validation error reaches the caller. Argument validation re-raises it as `InvalidArgumentError` in the package's message format.
- [x] Tests cover each error's code, its exception class and its message content: the available columns, the closest match and the allowed values.

Statistics:

- [x] Per column, the result gives the count; the missing, infinite, zero and negative counts; the mean; the standard deviation with ddof 1; the minimum and maximum; the quantiles; the median; the trimmed mean; the raw MAD and the MAD scaled by 1.4826 for consistency with the normal distribution; the bias-corrected skewness; and the bias-corrected excess kurtosis. Moments use finite values only.
- [x] `quantiles` defaults to 0.01, 0.05, 0.25, 0.5, 0.75, 0.95 and 0.99. `quantile_method` takes NumPy's quantile methods and defaults to linear. `trim_fraction` defaults to 0.1, cut from each end. The result records the values used and states each statistic's definition.
- [x] The numbers match SciPy's `skew` and `kurtosis` with `bias=False`, `trim_mean` and `median_abs_deviation`, and NumPy's quantiles for every quantile method, within a stated tolerance. Counts match pandas.
- [x] The standard deviation with fewer than 2 values, the skewness with fewer than 3 values or zero variance, and the kurtosis with fewer than 4 values or zero variance are null, and a limitation names the field path and the reason. NaN and infinity never appear in the record.
- [x] Integers beyond 2^53 add a float-precision limitation.
- [x] Nullable integer and float columns and pyarrow-backed numeric columns give the same numbers as their NumPy equivalents.
- [x] Findings cover constant columns and infinite values.

Statuses and warnings:

- [x] The result keeps one entry per column, keyed by column name, with its own status and, when it didn't complete, the reason. The overall status is `completed` when every selected column completed and `partial` when some did. When none did, it is the status the columns share, or, if they differ, the first of `failed`, `insufficient_data` and `not_applicable` that occurs.
- [x] The declared statuses are `completed`, `partial`, `insufficient_data`, `not_applicable` and `failed`. An empty DataFrame, or columns without values, give `insufficient_data`. A DataFrame without numeric columns gives `not_applicable`.
- [x] Numerical RuntimeWarnings raised inside the analysis, for division by zero, invalid values, overflow or precision loss, become limitations next to the numbers they affect. No warning reaches the caller.
- [x] Callers never see a DeprecationWarning or FutureWarning from inside an analysis, yet the test suite still fails when one is raised.

Done:

- [x] The docstring has the seven sections and passes the contract test. describe_dataset's `When to use:` and `See Also:` now point to summarize_numeric.
- [x] The catalogue entry is marked implemented, with its differences noted, among them the optional `columns`, the added `quantiles` and `quantile_method`, and weights deferred.

## Comments

What this ticket settled that the spec left open:

- **Validation strictness, 01's "For ticket 02".** A list option takes any ordered list-like: a list, a tuple, a pandas Index such as `df.columns[:3]`, a Series, a 1-D NumPy array or a generator. It also takes a single value as a one-item list, as pandas' `subset=` and `q=` do, so `columns="age"` and `quantiles=0.5` work. NumPy scalars become Python scalars, inside lists too. A set raises `invalid_argument`, because hashing decides its order. A column option also takes labels that aren't strings and names them by their string form, so `columns=[2, 0]` and `columns=["2", "0"]` give the same result. Everything else stays strict, so `"0.1"` and `True` are no floats. The registry's `_normalize` does all this from each option's annotation and name, before pydantic validates. The annotations stay canonical, such as `Sequence[str] | None`, because they become ticket 04's JSON Schema, and JSON Schema can't describe NumPy types. Tests that pass other list-likes carry a `ty: ignore` with the reason.
- **Ranges live in the signature**, as `Annotated[float, Ge(0), Lt(0.5)]` with annotated_types. pydantic depends on annotated_types, so it isn't a seventh dependency. `help()` shows the range, pydantic checks it and the JSON Schema carries it for ticket 04. The registry now reads annotations with `include_extras=True`. A message states a range as `float with 0 <= trim_fraction < 0.5` and shows a bad value in a list with its position, as in `got 1.5 at quantiles[1]`. An unknown choice lists every allowed value and the closest one, matching case and surrounding spaces first.
- **Shared column rules** live in `agent_eda/_columns.py`. `column_kind` classifies a dtype by its kind code into numeric, boolean, datetime, timedelta, categorical, text, object and other. Numeric covers kinds i, u and f plus pyarrow decimals; text covers StringDtype and Arrow strings. Each analysis declares a `ColumnRule` with the kinds `columns=None` selects, the kinds it accepts by name, the wording for both and a fix per rejected kind. `select_columns` returns a `Selection` with the columns and the names the default left out. It checks an empty list, repeated names, unknown names and unsupported kinds, in that order, and each error names every offending column at once. `check_distinct` in `_run.py` also rejects repeated quantile levels. An unknown name gets up to 3 suggestions, names that differ only in case or surrounding spaces first, then difflib's. The message lists up to 20 of the data's columns and counts the rest. Ticket 06 adds the summarize_categorical pointer to `_NUMERIC.fixes["categorical"]`.
- **Column labels.** The registry checks them for every analysis registered without `any_column_labels=True`, and only describe_dataset passes it. One code, `ambiguous_column_labels`, covers the three problems. MultiIndex columns get their own message; repeated and colliding labels share one, each with a one-line fix. describe_dataset's label logic moved into the shared `Labels` class, so its findings and this check can't disagree.
- **Statuses.** `ColumnResult` in `agent_eda.results` is the base of every per-column entry, with `column`, `status` and a `status_reason` that is null exactly when the column completed. `overall_status` in `_run.py` sets the result's status. Data without rows gives `insufficient_data` with code `no_rows`, numeric columns or not, so `pd.DataFrame()` gets it too. Rows without any selected column give `not_applicable` with the analysis's own reason, here `no_numeric_columns`. Otherwise the result is `partial` with code `incomplete_columns`. When no column completed, it takes the status the columns share, else the first of failed, insufficient_data and not_applicable, with the code of the first column that has it. summarize_numeric's columns end either completed or insufficient_data, with code `no_finite_values`, so the branch for differing statuses has no test yet. As in describe_dataset, `failed` is declared, as the ticket asks, but no code path returns it.
- **Entries are keyed by column name**, so `res.columns["age"].median` works. Field paths read `columns['age'].std`, and a limitation about a whole column points at `columns['age']`. `quantiles` is a dict keyed by level, read as `res.columns["age"].quantiles[0.95]`. In JSON the keys are the level's repr, `"0.95"`, and `to_frame()` names the column `q0.95`. The result adds `left_out_columns`, capped like other lists, and `definitions`, which the analysis builds from the entry fields' descriptions so the text exists once.
- **Definitions.** `count` counts values that aren't missing, infinite ones included. `missing_count` counts NaN after reading the column as float64. A pyarrow float column, or a nullable float one on pandas 2, can store NaN as a value that pandas' isna() doesn't count; summarize_numeric counts it as missing and adds a `nan_counted_as_missing` limitation. Only then does its count exceed describe_dataset's. Every statistic uses the finite values, not only the moments, and `negative_count` includes -inf. The median ignores `quantile_method`. The MAD scale is exactly 1.4826, while SciPy's `scale="normal"` is 1.482602, so the tests pass `scale=1/1.4826`. A column is constant as describe_dataset decides it: at least two values that aren't missing, all equal. So `[inf, inf]` is constant and `[5, 5, inf]` isn't. Skewness and kurtosis are null for zero variance when the smallest and largest finite values are equal; SciPy's rounding test plays no part.
- **Moments about the median.** summarize_numeric subtracts the median before computing moments, so they stay exact for large values close together. On `1e6 + N(0, 1)`, SciPy and pandas lose 5e-9 of the skewness. On `1e15 + [0, 1, 2, 3, 10]`, the plain two-pass formula loses 1e-4 of the standard deviation. agent-eda matches exact rational arithmetic to 1e-14 on both. So the SciPy reference test passes `x - median(x)`, which changes neither statistic, and a second test compares with `fractions.Fraction`.
- **Numerical warnings.** Each group of statistics runs inside `watch_warnings()` from `_run.py`, which records NumPy's floating-point errors as warnings whatever `numpy.seterr` says. When a statistic comes out inf or NaN, summarize_numeric computes it again on the values divided by a power of two, which loses nothing. A statistic stays null only when float64 can't hold the result, such as the standard deviation of ±1.7e308. Its `numerical_warning` limitation names each such field and quotes NumPy's messages. Overflow that the second pass removes, such as summing values near 1.7e308, leaves no limitation, because the reported number is exact. The shift about the median keeps precision loss out of the moments.
- **Warning policy.** The registry runs every analysis inside `watch_all_warnings()`. It turns a RuntimeWarning that the analysis didn't tie to particular values into one `numerical_warning` limitation without fields. It raises every other warning again under the caller's own filters but shows it to no one. A caller whose filters turn the warning into an error gets that error, and the suite's filters do so for DeprecationWarning and FutureWarning. The tests provoke both cases through describe_dataset, with object values whose `__hash__` warns. A future rename shim has to call `warnings.warn` outside the wrapped call, or the wrapper swallows its warning.
- **New limitation codes:** `too_few_values`, `zero_variance`, `numerical_warning`, `float_precision`, `boolean_as_numeric` and `nan_counted_as_missing`. `float_precision` flags integers beyond ±2^53, which the analysis finds with the column's own `max()` and `min()`. A result lists one limitation per code, the reading ones first, then the ones that explain nulls.
- **Contract test.** A parameter whose annotation takes `str` must end in `column` or `columns` or appear in `NOT_COLUMN_NAMES`, which holds `source` and `source_version`. A new text parameter fails the suite until someone decides which it is.

Measurements, on an M3 Max with Python 3.12.11 and BLAS limited to 2 threads, using the research notes' 1M x 100 frame with 30 float64 columns that hold NaN and ±inf and 15 Int64 columns: summarize_numeric took 1.3 s on pandas 3.0.6 with numpy 2.5.4 and 1.5 s on pandas 2.2.0 with numpy 1.26.0. Ticket 03 times it on its own benchmark and on the target machine.

- Minimum versions: `uv run --isolated --resolution lowest-direct --python 3.12 pytest` passed with numpy 1.26.0, pandas 2.2.0, scipy 1.11.2, pydantic 2.7.0 and pyarrow 14.0.1, and left `uv.lock` unchanged. Python 3.13 and 3.14 passed with `uv run --isolated --python 3.1x pytest`.

It covered empty and single-value columns, all-NaN and inf-only columns, values near ±1.7e308, subnormals, int64 and uint64 extremes, sparse and pyarrow columns, three quantile methods and three trim fractions.
