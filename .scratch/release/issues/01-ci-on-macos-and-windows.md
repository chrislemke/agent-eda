- Fixed in the code (real bugs on Windows, no change on Linux and macOS):
  - A path shown in a message had every backslash doubled, because it went through `repr`: `'C:\\Users\\...'`, and doubled again inside the MCP server's JSON. A Windows caller who copies the path back would pass the doubled one. `agent_eda._text.quoted_path` writes the path in quotes as it is (it still uses `repr` for a path with a quote or a character that can't be printed); the messages of `Project.load`, `Project.save`, the MCP `data_path`, `table_path` and `project_path` use it. The code a message suggests, such as `project.save('config\\project.toml')` or `os.makedirs(...)`, stays `repr`, which is right for a Python literal.
  - A Windows path that holds a character no file name can, such as the `:` of `http://host/orders.csv`, raises `OSError` with `winerror` 123, whose errno is EINVAL, so the MCP server answered `unreadable_data_file`, not `data_file_not_found` as on Linux and macOS, where nothing is at that path. `names_nothing` in `_wording.py` recognizes it, and `data_path` answers `data_file_not_found`. A name part of more than 255 characters raises the same error 123, so `os_cause` tells the two apart by the length of the parts of `error.filename` and says "longer than 255 characters" for the long one, as it does for ENAMETOOLONG on POSIX. `winerror` 206 says it too. `table_path` gets the same wording.
  - `compute_association_matrix` ordered pairs by the exact bits of their absolute values. Its sums run through the machine's BLAS, whose last bits differ between CPUs (macOS Accelerate against OpenBLAS on x86_64 and ARM64 gave 1.0 against 0.9999999999999996 for an exact relation), so pairs that are tied for every practical purpose came out in another order on each CPU, and the printed top 10 differed. `_strongest_first` now rounds the absolute value to 12 decimals before it sorts, so ties keep the selected column order, as the field description says. The values themselves are unchanged, so records still differ in their last digits between CPUs, as the README says ("in the same environment, BLAS thread count included"). The benchmark of the analysis: 0.88 s on 1,000,000 rows x 100 columns.
- Fixed in the tests (the test was wrong; each assumed POSIX): `test_argument_messages` expected `PosixPath` where a Windows caller gets `WindowsPath`; `test_a_path_that_looks_like_a_url_is_a_local_path` and its expected messages used `os.sep` after the working directory; tests that built the expected text of a message with `repr` of a path (`tests/test_project_files.py`, `tests/test_mcp_data.py`, `tests/test_mcp_fixes.py`) now expect the quoted path of the message, and the code a message suggests as `repr`; `test_a_text_that_is_already_full_loses_a_line_to_the_table_path_line` assumed that the line "Full table written to <path>" fits in 120 characters, which depends on the runner's temporary directory (macOS runners' are long, as are Windows'), and now accepts the two-line form the code is meant to write; `test_discovery_leaves_scipy_statsmodels_sklearn_and_the_network_alone` took `socket.gethostname`, which pandas' import reaches on Windows through `platform.machine()`, for network use, and now ignores only that event (reading this machine's own name opens no connection); two new tests (`test_a_data_path_with_a_character_windows_refuses_in_a_name_has_no_file` and `test_a_data_path_with_a_name_of_300_characters_that_windows_refuses_says_so`) craft an `OSError` with `winerror = 123` so that the branches also run on Linux and macOS; `{directory}/missing.toml` in the MCP message table mixed separators, which the code rightly shows with where it leads (`(<tmp>/missing.toml)`), and is now `{missing}`; the tests of `Project.save` and `Project.load` that expected `'config\\project.toml'` in a message follow the quoted path.
