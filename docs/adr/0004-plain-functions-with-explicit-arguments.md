# Analyses are plain functions with explicit arguments

The original catalogue of planned analyses gave every analysis a required `context: AnalysisContext` carrying a run ID, project config, dataset roles, alpha, confidence level, seed, budget and policy. We dropped it: an agent or a person should be able to call `summarize_numeric(df, columns=["age"])` without building anything first. Each analysis takes only the settings it uses, as typed keyword arguments. Standard conventions such as `seed=0` and `confidence_level=0.95` have defaults that the result records; project-specific values such as thresholds, units and time cutoffs never get defaults. Dataset roles and the data policy travel in an optional `Project`, passed only to analyses where roles or the data policy matter (the policy's masking applies wherever a result can show raw values); without one, checks that depend on roles report "not checked", never "passed".
