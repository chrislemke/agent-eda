# Local MCP server over stdio, data by path

Agents that call tools instead of writing Python can reach the analyses through a local MCP server, shipped in this package behind the optional `mcp` extra so that the core still installs in Code Interpreter without it (ADR 0005). The server speaks only stdio, as a subprocess of the client, so the package still makes no network connections. An MCP client cannot pass a DataFrame, so every MCP tool takes a data path and reads the file itself, with only empty CSV fields counted as missing so that sentinel values reach the analyses; we rejected dataset handles held in server memory because results would then depend on earlier calls, and inline rows because only toy data fits. Each analysis becomes one typed MCP tool generated from the registry and its docstring, rather than one generic `run_analysis` tool with an untyped arguments object, so clients validate arguments and nothing is maintained twice; if the planned analyses make the tool list too long, the server can expose a preset instead. The server is the kind of separate process ADR 0001 mentions, but it does not make the data policy access control: the agent can usually still read the files directly, so masking remains a guardrail and the server makes no enforcement claims.

A call returns the printed result as text and the result record as structured content. Claude Code shows the model only the structured content, and on 1,000 rows x 100 columns we measured records of 26 to 78 KB per call against about 1.2 KB of text. We keep both parts anyway: other clients show the text, and the record holds every field an agent reads. So the server's instructions don't promise that the caller sees the text, and the path and row count of a table written with `table_path` go into the record as well as the text. Analyses that take DataFrames by role, such as `before=` and `after=`, will need one path argument per role. The server doesn't build that yet and refuses to start with such an analysis, so the first one has to extend it.
