# Local MCP server over stdio, data by path

Agents that call tools instead of writing Python can reach the analyses through a local MCP server, shipped in this package behind the optional `mcp` extra so that the core still installs in Code Interpreter without it (ADR 0005). The server speaks only stdio, as a subprocess of the client, so the package still makes no network connections. An MCP client cannot pass a DataFrame, so every MCP tool takes a data path and reads the file itself, with only empty CSV fields counted as missing so that sentinel values reach the analyses; we rejected dataset handles held in server memory because results would then depend on earlier calls, and inline rows because only toy data fits. Each analysis becomes one typed MCP tool generated from the registry and its docstring, rather than one generic `run_analysis` tool with an untyped arguments object, so clients validate arguments and nothing is maintained twice; if the catalogue makes the tool list too long, the server can expose a preset instead. The server is the kind of separate process ADR 0001 mentions, but it does not make the data policy access control: the agent can usually still read the files directly, so masking remains a guardrail and the server makes no enforcement claims.
