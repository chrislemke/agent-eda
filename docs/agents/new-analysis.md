# Adding or renaming an analysis

An analysis touches about a dozen places. Work through the steps in order. The last column says what catches a miss; where it says "nothing", only you do, so check it by hand. Run `uv run pytest` after each step: most misses fail a test that names the fix.

| # | Step | What catches a miss |
| --- | --- | --- |
| 1 | **Name it.** Verb first, unique across the package, in the glossary's words (`GLOSSARY.md`). Take the proposed name and module from `docs/planned-analyses.md`, unless the ticket or spec overrides them. An analysis that runs a statistical hypothesis test keeps a natural `test_*` name. Read the ADRs that apply (`docs/adr/`): ADR 0004 for the call pattern, ADR 0006 for what an MCP caller reads. | A name used twice raises `TypeError` when the second module is imported. A test function named like an analysis fails `tests/test_suite_rules.py`. The glossary: nothing. |
| 2 | **Write the test first** through the public API, with a small hand-built DataFrame (`/tdd`). Check numbers against SciPy, statsmodels or pandas. | Review. |
| 3 | **Write the function** in its submodule of `agent_eda.data` or `agent_eda.statistics`: `def name(data, *, ...)`, decorated with `@analysis(statuses=..., finding_codes=..., tags=..., methods=..., masking=..., work_limits=...)` from `agent_eda._registry`. | `tests/test_exports.py` fails for a public function in those packages that isn't registered, and for one that isn't exported. |
| 4 | **Write the result class** in `agent_eda/results.py`: `<Name>Result`, a subclass of `AnalysisResult`, with a description on every field, fractions named `…_share` and a limitation for every null. | `tests/test_contract.py`: class name, field descriptions, statuses and finding codes that the decorator declares. |
| 5 | **Export it** from `src/agent_eda/__init__.py` in all three lists: the `TYPE_CHECKING` imports, `__all__` and `_EXPORTS`. A new module must also be in `_EXPORTS`, or `ae.list_analyses()` never imports it. | `tests/test_exports.py` fails when the three lists name different sets. |
| 6 | **Write the docstring** in the seven parts of AGENTS.md's Docstrings section, with every declared finding code under Returns, each bullet starting with its assessment and a semicolon (the Reference copies it), the reason codes of each status but `completed` ending its `Statuses:` entry (``Reason code: `no_rows`.``; take them from `StatusReasonCode` in `results.py`, or add a code there with its comment), and a runnable example. Keep each argument's text in `Args:`, because it becomes the MCP tool's schema description. | `tests/test_contract.py`: sections and their order, `Args:` against the signature (each entry's type, the choices of a `Literal` and what `None` means), codes and their assessments, statuses, the example, which runs once. `tests/test_status_codes.py`: every declared status and reason code is returned for some data in its table, and an undeclared reason code raises. The Reference is generated from the docstring (step 12). |
| 7 | **Update the neighbours.** Where the new analysis is the better answer to a neighbour's question, edit that neighbour's `When to use:` and `See Also:`. | The contract test only checks that each See Also entry is an analysis in `ae.list_analyses()` and that the names in `When to use:` exist. Whether they are the right ones: nothing. |
| 8 | **Make it findable.** Add `tags=` words that agents use for it, and an entry to `SYNONYMS` in `agent_eda/_search.py` only for a word agents use for a package word. If it belongs to the first look, add it to `FIRST_LOOK` in `agent_eda/discovery.py`. | `tests/test_contract.py` (searching for its name finds it first), `tests/test_search_analyses.py`, `tests/test_guide.py` and `tests/test_mcp_discovery.py`. The guide and the MCP instructions are capped at 60 lines each, and a new analysis can break the cap: fix it as `.scratch/audit/findings.md` DOC-4 describes. A search word nobody tests: nothing. |
| 9 | **Add a recipe** to `RECIPES` in `tests/recipes.py`: valid arguments for any DataFrame. It puts the analysis into the property, masking, benchmark and MCP contract tests. | `tests/test_properties.py` fails for an analysis without a recipe. Its `check_contract` then holds every result to the rules: capped lists with their `_total`, finding and limitation paths that resolve, each finding's assessment as the docstring documents it, `to_dict()` equal to `to_json()`, no timestamps or HTML. |
| 10 | **Check the MCP surface** (AGENTS.md, rule MCP surface). Each raise site an MCP tool can reach builds its message with `agent_eda._wording.worded`, so the fix is one an MCP caller can make. Every parameter type has a JSON Schema. An analysis that takes several DataFrames by role needs a `<role>_path` argument per role, which the server can't build yet (ADR 0006). | `tests/test_mcp_tools.py` (the description's sections, a schema for every parameter), `tests/test_mcp_wording.py` (no Python syntax in any description, input schema or mistake message; a new error code needs a row in `MISTAKES` of `tests/test_mcp_argument_messages.py`), `tests/test_mcp_errors.py`, `tests/test_mcp_fixes.py`. Docstring sections that read wrong over MCP and a message that is right in Python and wrong over MCP in a way the guard can't see: nothing, so read yours. |
| 11 | **Add a new error code** only for a new kind of caller mistake: a subclass of `AgentEDAError` with a stable `code` in `agent_eda/errors.py`. Add it to the `ae.errors` docstring; the errors table in the README's Reference is generated from it (step 12). | `tests/test_error_codes.py` fails for a code missing from the docstring or the README's errors table and for a documented code nothing raises. |
| 12 | **Update the README.** Move the analysis from the backlog, `docs/planned-analyses.md`, to the README's Analyses section: into the first-look table if it is in `FIRST_LOOK`, otherwise into the "Other analyses" table under its module. Delete its row from `docs/planned-analyses.md`. Fix the counts that name how many analyses there are. Regenerate the Reference with `scripts/generate_reference.py` (the command is under AGENTS.md's Commands), and again after any later change to a docstring, a signature or a result field description: the Reference is generated from them, never edited by hand. | `tests/test_readme.py`: each analysis in exactly one table, the backlog holds no shipped analysis, and a stale Reference, which fails with the command to run. The counts in prose: nothing. |
| 13 | **Add glossary terms** for any new concept the analysis reports, with an Avoid line. | Nothing. |
| 14 | **Run the benchmark** if its cost grows with rows or columns (the command is in AGENTS.md's Finish checks). Analyses whose cost grows faster than the row count take `max_*` arguments. | `tests/test_contract.py` (work limits come with `budget_exceeded`); the 5-second limit: only the benchmark run. |
| 15 | **Run the finish checks** in AGENTS.md. | CI. |

## Renaming an analysis

A renamed analysis keeps its old name working for two minor releases, with a warning that names the replacement (`warnings.warn` is reserved for this). Repeat steps 3, 5, 7, 8 and 10 to 13 for the new name, and keep the old name in `__all__`, `_EXPORTS` and the `TYPE_CHECKING` imports. No renamed analysis exists yet, so the first rename adds the shared alias mechanism and its test.
